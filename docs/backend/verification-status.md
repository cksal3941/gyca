## 실행 방법과 결과

저장소 루트에서 `node scripts/verify-backend.mjs`를 실행한다. 스크립트는 자신의 위치를 기준으로 작업 경로를 정하고, tests/*.test.mjs 전체 → 프로젝트 TypeScript 검사 → 서버·계약·API·테스트 ESLint 순서로 실행한다. 실패하면 다음 단계로 넘어가지 않고 종료 코드 1을 반환한다. DB 마이그레이션·배포·실결제는 실행하지 않는다.

이번 결과: 테스트 184개 모두 통과, 전체 타입 검사 통과, 지정된 서버 범위 ESLint 통과. [실행 로그](verification-2026-09-16.log)에 출력이 남아 있다. Node의 MODULE_TYPELESS_PACKAGE_JSON 경고는 발생했으며 테스트 실패는 없었다. 프런트 전체 스타일 검사와 프로덕션 빌드는 이 명령에 포함하지 않는다.

## 검증한 범위

- 공통 전송 계약, 공모 공개·접수 정책, 관리자 권한과 공모별 접수 목록.
- 파일 소유권·형식/크기·PDF 페이지 수 검사, 검사 중 삭제와 재시도.
- 3종 동의문 고정, 보호자 이메일 수락 증적, 제출 내용 변경 차단.
- 결제 금액·통화·가맹점 대조, 중복 승인 방지, 지연 통지, 마감 시각, 복구 작업 및 접수번호 발급.
- 실제 Toss HTTP 응답 형식에 대한 로컬 테스트와 서버 원장 연결. 실제 Toss 승인 요청은 아님.
- 접수 이메일의 재시도·동일 발송 키 유지, 이메일 확인 토큰과 로그인 제한.

## 이 결과로 확인되지 않은 것

DB 테스트는 PGlite이며 운영 PostgreSQL 연결·동시성·마감 직전 부하를 증명하지 않는다. S3 테스트는 SDK 서명 및 가짜 응답으로 검증했고 실제 버킷·CORS·브라우저 업로드는 남아 있다. 이메일 전달, PG 실계약·해외 카드·EUR 지원, 실제 결제 승인/취소·정산, Docker 이미지 실행, 화면 전체 동선은 확인하지 않았다.

따라서 오픈 준비 완료 판정은 아니다. 외부 계정 구성, 운영 정책 확정, 실제 화면/서버 연결 후 스테이징에서 접수→결제→접수 확인을 검증해야 한다. 기존 비활성 플래그와 canOpen=false는 유지한다.
