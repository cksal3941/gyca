# 토스페이먼츠 해외결제 검토

확인일: 2026-09-15. 사용자 의견에 따라 토스페이먼츠 해외결제를 우선 검토 대상으로 삼는다. 실제 가맹 계약이나 EUR 지원 확정은 아니다.

후속 구현: 서버 승인·조회 어댑터와 테스트 전용 연결 설정을 추가했다. [최신 구현·검증 범위](toss-adapter-implementation.md)를 참고한다. 계약 조건은 여전히 확인이 필요하다.

## 원본 요구사항과 확인 결과

- DOCX `GYCA_Leipzig_2027_UIUX_기획서.docx`에는 STEP 6 €70 결제와 결제 성공 후 접수번호·내역 제공 요구가 있다. 이 문서의 텍스트에서는 특정 PG 이름을 찾지 못했다.
- 붙여넣은 Website Planning & Development Brief의 결제 절은 KRW/USD/EUR 대응 검토와 국내·해외 카드 결제를 요구하며, 국내/해외 PG는 미팅 결정 항목이다.
- 따라서 €70이라는 현재 계약을 유지하고 결제 수단 선정 때문에 임의 환산하지 않는다. 해외 전시 아카이브나 작품 판매 결제를 이번 참가비 주문에 포함하지 않는다.

## 공식 문서에서 확인한 내용

토스의 해외 카드 결제는 KRW가 기본이며, 다통화는 별도 계약과 지원 통화 확인이 필요하다. PayPal은 USD로 안내된다. 하나의 MID는 하나의 통화에 대응하므로 서로 다른 청구 통화는 MID별 구성이 필요하다. 이 안내만으로 EUR 청구 가능 여부를 확정할 수 없다. [토스 해외결제 연동하기](https://docs.tosspayments.com/guides/v2/learn/foreign-payment)

토스 결제는 요청·인증·승인 단계로 나뉜다. 성공 페이지로 돌아온 것은 서버 승인 완료와 다르므로 주문·금액을 대조하고 서버에서 승인 결과를 확인해야 한다. [결제 흐름](https://docs.tosspayments.com/guides/v2/get-started/payment-flow)

클라이언트 키와 시크릿 키는 가맹점·환경에 맞는 세트를 사용해야 하며 시크릿 키는 브라우저나 저장소에 노출하면 안 된다. 테스트 키의 승인은 실제 차감이 아니다. [API 키 안내](https://docs.tosspayments.com/reference/using-api/api-keys)

## 계약 전에 확인할 구체적인 질문

아래는 문의용 초안이며, 외부로 발송하지 않았다.

> 국제 청소년 아트북 공모 참가비를 작품당 EUR 70으로 온라인 수납하려 합니다. 당사의 계약 주체·소재국 조건에서 해외 카드 EUR 직접 청구가 가능한지, EUR용 MID와 테스트 키를 발급할 수 있는지 확인 부탁드립니다. 가능한 카드 브랜드·참가국 제한, 청구/정산 통화, 수수료·환불·차지백 조건, 참가비 업종 심사 조건도 안내 부탁드립니다. 국내 참가자도 같은 EUR 결제 경로를 이용할 수 있는지와 지원되지 않을 경우 가능한 대안을 알려주세요.

사용자에게는 계약 주체와 토스의 EUR 지원 확인 결과가 필요하다. 비밀 키는 채팅으로 받지 않고 개발 환경의 비밀 설정에 보관한다. 미지원 시 청구 통화 변경을 임의 결정하지 않고 다른 EUR 결제 경로와 비교한다.

## 다음 연결 순서

1. EUR 청구·계약 주체·MID·테스트 환경 확인.
2. 토스의 해당 결제 상품·SDK 버전에 맞는 결제 요청/서버 승인 계약 작성. 내부 `amountMinor:7000`을 공급자 단위로 변환할 때 공식 규격을 대조한다.
3. 서버 승인·조회 어댑터 구현. paymentKey는 결제 확정의 증거가 아니라 조회/승인을 위한 참조이며, 서버 주문과 금액을 대조한다.
4. 토스가 제공하는 실제 웹훅 인증·조회 방식에 맞춰 정규화한다. 시험용 공급자의 HMAC 방식을 복사하지 않는다.
5. 테스트 DB와 테스트 MID를 운영 DB/라이브 키와 분리하여 승인·실패·취소·지연 알림·재전송을 검증한다.
6. 환불·운영 확인·자동 재확인과 알림 worker를 연결하고 운영 마감 정책을 승인받는다.

현재 구현은 공급자와 무관한 주문·검증 원장이다. 토스 결제창과 승인 API가 이미 연동되었다고 안내하지 않는다.
