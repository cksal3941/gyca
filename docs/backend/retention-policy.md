# 파일·증적 보관 정책

2026-09-18. 운영자가 기간을 결정하기 전에 코드가 임의 삭제하거나 무기한 보관하지 않도록 공모별 정책 계약과 관리자 API를 추가했다.

## API

- GET `/api/v1/admin/competitions/{competitionId}/retention-policy`
- PUT `/api/v1/admin/competitions/{competitionId}/retention-policy`

PUT은 `{revision,policy}`이며 정책은 다음 기간을 각각 명시한다.

- 철회된 미제출 초안 파일 삭제까지의 일수
- 미입상 제출 파일 삭제까지의 일수
- 수상·선정 제출 파일 삭제까지의 일수
- 접수 당시 동의 증적 보관 일수
- 결제 증적 보관 일수

모든 숫자는 운영자가 결정한 정수 일수이며 서버에 기본값이 없다. version도 필수다. 동의·결제 증적과 작품 파일을 같은 기간으로 취급하지 않는다.

실제 공모 운영자만 조회·수정할 수 있다. 접수나 결제가 활성화됐거나 접수 건이 생긴 뒤에는 변경할 수 없다. revision 충돌을 검사하고 migration 022에 정책 원문·담당자·시각을 변경 불가능하게 기록한다.

## 철회 초안 파일 파기 실행

미제출 초안을 철회하면 같은 DB 트랜잭션에서 정책 버전, 파일 키, S3 VersionId와 삭제 예정 시각을 `gyca_asset_deletion_jobs`에 고정한다. 정책이 없거나 서버가 정확한 VersionId를 확보하지 못한 파일은 추측해서 삭제하지 않는다.

`POST /api/internal/storage/retention`은 전용 bearer token과 활성화 플래그가 있는 내부 작업자다. 만기가 지난 작업 하나를 임대하고 별도 최소 권한 S3 자격 증명으로 정확한 VersionId만 영구 삭제한다. 실패는 지수 지연으로 재시도하고 8회 뒤 `stalled`로 멈춘다. 결과는 변경 불가능한 이벤트로 남고 공급자 오류 원문은 저장하지 않는다.

철회된 미제출 초안과 최종 공개된 미입상·선정 결과 파일이 파기 예약에 연결된다. 결과 공개 시 미입상과 선정 파일에 서로 다른 기간을 적용하며 공개·감사 기록·파기 예약은 한 트랜잭션이다. 운영 알림과 실제 AWS/IAM·스케줄러 검증은 남아 있어 launch-readiness의 `retention`은 계속 `unverified`다.

## 검증

권한, Origin, 엄격한 입력, 기간 범위, revision 충돌, 접수 생성 후 변경 차단, 철회와 예약의 원자성, 정확한 버전 삭제, 만기 전 차단, 재시도, 오류 비노출과 감사 불변성을 검증했다. 실제 보관기간 값과 법률 검토는 운영 결정 사항이다.
