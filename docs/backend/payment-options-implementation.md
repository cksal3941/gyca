# 국내·해외 결제 경로 안내 기반

후속 업데이트: [결제 경로의 주문 고정](routed-orders-implementation.md)에서 policyToken과 create_order 액션, 경로를 받는 주문 생성 API를 추가했다. 아래의 항상 빈 allowedActions 및 주문 미연결 설명은 이전 단계 기록이다.

2026-09-15. 이번 구현은 **후보 경로 조회**까지다. 복수 PG 결제 시작·전환을 활성화한 것이 아니다.

## 구현

`GET /api/v1/entries/{entryId}/payment-options`는 로그인한 본인의 제출 건에 대해 서버에 저장된 거주국·EUR 참가비·결제 마감으로 후보를 판정한다. URL에 국가나 금액을 넣어도 판정에 사용하지 않는다. 거주국은 안내 분류 기준이며 카드 발급국이나 승인 가능 여부를 증명하지 않는다.

공모전의 `payment_routing` 정책에는 버전과 경로 목록을 저장한다. 경로마다 고유 id, enabled, provider, merchantAccount, liveMode, countries(명시적 국가 목록), currency(EUR), approvalReference(운영자가 확인한 가맹 조건 근거), EN/KO label과 refundNotice가 필요하다. 기본 정책은 NULL이다. 승인 근거 문자열은 외부 승인을 자동 검증하는 장치가 아니므로 운영자가 확인 후 설정해야 한다.

지원 국가·통화·가맹점·시험/운영 모드가 모두 맞고 해당 공급자가 서버에 설정된 경우에만 후보를 반환한다. 국내를 KR, 해외를 무조건 나머지 전체로 간주하지 않는다. 실수로 미지원 국가를 허용하는 기본값은 없다. 공급자 ID나 가맹점 비밀 식별자는 응답에 포함하지 않는다.

기존 주문이 있으면 실패 상태여도 새 후보를 반환하지 않는다. 주문 생성 후 승인 결과가 불명확한 상태에서 다른 PG를 이용하면 중복 과금할 수 있으므로, 후속 전환 기능에는 기존 시도 확정 조회와 주문·시도 분리가 필요하다.

## Claude 전달용

`@/contracts/payment-options`의 PaymentOptionsSchema/PaymentOptions를 사용한다. 응답은 기존 `{data,meta}` 봉투이며 data는 entryId, country, money, routes, allowedActions, blockingReasons다. 각 후보에는 id, label, mode(test/live), refundNotice가 있다.

**allowedActions는 현재 항상 빈 배열이며 이 응답으로 결제 시작 버튼을 활성화하면 안 된다.** routes는 계약·설정상 후보 안내다. 결제창 연결이 남아 있어 후보가 있더라도 PAYMENT_UNAVAILABLE을 반환한다. 기존 주문은 ENTRY_LOCKED, 마감은 DEADLINE_PASSED, 미설정은 POLICY_NOT_CONFIGURED로 구분한다. 401/404와 private,no-store는 기존 본인 API 규칙을 따른다.

이 GET은 주문을 만들거나 동의·환불 규정 수락 증적을 저장하지 않는다. 후보의 환불 안내는 현재 정책이다. 실제 선택 시 경로·조건 버전을 주문에 고정하고 필요한 동의 증적을 남기는 작업이 다음 단계다.

## 아직 남은 작업

- 선택한 경로를 주문 생성에 강제하고 승인·웹훅·복구를 해당 공급자로 전달하는 연결.
- 경로별 조건 고정, 복수 결제 시도와 안전한 전환, 실제 결제창.
- PayPal/Stripe 등 추가 공급자 선정·가맹 조건 확인·어댑터 구현. 현재 런타임은 기존 토스 테스트 설정만 인식한다.
- 운영 DB의 009 마이그레이션과 승인된 정책 설정. 이번에는 실행하지 않았다.
- 작품 이용허락의 운영 문구, 보호자 확인, 보관기간·파기 정책과 기능은 계속 미완료이며 결제 경로 구현과 별도로 필요하다.

기존 주문 생성 API는 이 안내 정책을 아직 소비하지 않는다. 따라서 이 기능만으로 국가별 결제 제한이 전체 결제 흐름에 강제된다고 볼 수 없다. 실결제는 활성화하지 않았다.

## 검증

격리 PGlite 테스트로 국내/해외 후보 분리, EUR 유지, 미지원 국가·미설정 공급자·모드 불일치 차단, 정책 누락·중복 ID·승인 근거 누락, 마감 경계, 기존 주문의 전환 금지, 본인 접근·국가값 위조 방지를 확인한다. 실제 PG 승인 가능 여부와 카드 발급국별 지원은 이 테스트 범위가 아니다.
