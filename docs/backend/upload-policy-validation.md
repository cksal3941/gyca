# 업로드 정책과 서버 처리 규격 일치

## 공개 공모 API 후속 보정

공개 projectCompetition도 같은 supportsUploadRule 검사를 사용한다. 지원하지 않는 파일 상한/형식이 있으면 readiness.application=false와 POLICY_NOT_CONFIGURED를 반환하고 start_entry를 제공하지 않는다. 접수 생성 게이트도 이 판단을 사용하므로 화면만 숨기는 조치가 아니다.

또한 참가비 0원은 현재 주문 생성이 지원하지 않으므로 readiness.payment=false로 표시한다. 무료 접수 흐름을 추가한 것은 아니며 실제 참가비를 변경하지 않았다. readiness.payment=true도 PG 연결이나 결제창 사용 가능을 단독 보장하지 않는다. 실제 결제 경로와 allowedActions를 함께 확인한다.

이 두 불일치를 먼저 실패 테스트로 재현한 뒤 수정했다. 공개 공모·접수·업로드·제출 회귀 테스트 59개, 전체 타입 검사·관련 ESLint 통과. 프런트 파일과 DB 데이터는 수정하지 않았다.

오픈 준비 진단에서 실제 서버의 64MiB 제한을 넘는 정책이나 영상 형식을 form=configured로 표시하는 문제를 테스트로 재현하고 수정했다.

`src/server/uploads/policy.ts`의 공통 검사 기준:

- 최대 크기가 확정돼 있고 64MiB 이하여야 한다.
- 표지는 image/png 또는 image/jpeg이며 PDF 페이지 수 조건을 지정하지 않는다.
- 책 PDF와 계약상 증빙 문서는 application/pdf 형식이어야 한다.
- 허용 형식 목록은 비어 있을 수 없다.

관리자 launch-readiness, 신규 업로드 요청, 최종 제출 정책 검사에 공통 기준을 적용했다. 크기 상수는 실제 파일 검사에도 공유한다. 책의 최소 20쪽·필수 업로드 수 등 기존 제출 검사는 유지한다.

설정 저장 API 자체는 미완성 정책을 보관할 수 있다. 정책을 저장했다고 처리 가능 상태가 되는 것은 아니며 진단 결과와 서버 응답을 확인해야 한다. 이미 생성된 업로드 세션의 멱등 재조회 동작은 유지하고, 최종 제출 시 현재 정책 검사를 다시 거친다. 기존 접수 증적이나 저장 파일을 변경·삭제하지 않는다.

검증: 64MiB 경계/초과, 영상 형식, 책에 이미지 허용, 표지에 PDF 허용, 이미지 페이지 조건을 확인했다. 기존 업로드·실제 PDF/이미지 검사·제출 테스트 포함 36개, 전체 타입 검사·관련 ESLint 통과. 실제 S3/운영 DB 검증은 별도다. 프런트 코드는 변경하지 않았다.
