# 회원 이메일 소유 확인

2026-09-16. 기존 Better Auth의 이메일 확인 기능에 발송 함수를 연결했다. 실제 메일을 보내거나 계정을 생성하지 않았다.

## 활성화 전 조건

- `AUTH_EMAIL_VERIFICATION_ENABLED=true`를 명시해야 켜진다. 기본 false이며 Claude 화면 연결 전에는 활성화하지 않는다.
- 기존 Resend 설정과 검증된 발신 주소, HTTPS BETTER_AUTH_URL 필요. 메일러 설정이 없으면 발송 함수는 실패하며 확인 완료로 처리하지 않는다.
- 인증 마이그레이션을 다시 실행해 Better Auth의 `rateLimit` 테이블을 준비한다. scripts/migrate.mjs의 생성 옵션을 런타임 DB 제한 설정에 맞췄다. 기존 플랫폼 SQL 마이그레이션 변경은 없다.

## 동작

이메일/비밀번호 가입 시 확인 메일을 보내고, 확인 전에는 해당 방식의 로그인을 차단한다. 토큰 생성·검증·만료 판정과 emailVerified 갱신은 설치된 Better Auth가 담당한다. 유효기간은 1시간이다. 임의 emailVerified 입력이나 잘못된/만료된 토큰으로 검증되지 않는다.

확인 링크는 설정한 HTTPS origin의 `/api/auth/verify-email`만 허용하고 토큰 일치를 검증한다. 메일에 넣는 복귀 경로는 `/login`으로 고정한다. 확인 후 자동 로그인하지 않는다. 재발급이 이전 미만료 토큰을 즉시 폐기하는 방식은 아니다.

sendOnSignIn=false라 로그인 시도 때마다 메일을 보내지 않는다. 별도 재발송 버튼은 Better Auth sendVerificationEmail을 호출한다. DB 기반 HTTP 요청 제한은 재발송·가입 각 60초당 3회이며, 배포 프록시의 실제 클라이언트 IP 전달을 검증해야 한다. 사용자 입력으로 위조 가능한 프록시 헤더에 의존하지 않도록 운영 설정을 확인한다. 계정별/이메일별 추가 전송 한도는 아직 없다.

이 설정은 비밀번호 로그인 대상이다. 소셜 제공자의 확인 정책이나 이미 발급된 세션을 소급 차단하지 않는다. Google/Apple 실제 OAuth 흐름은 별도 검증이 필요하다. 보호자 신원 확인을 대신하지도 않는다.

발송 함수는 기존 메일 전송기를 공유하지만 접수 완료 outbox와 별개로 실행한다. 동일 토큰의 전송에는 동일 멱등 키를 사용한다. 발송 실패 시 성공으로 위장하지 않으며 사용자는 재발송을 요청할 수 있다. 가입 요청 오류 이후 계정 생성 여부는 Better Auth 처리 결과에 따라 달라질 수 있으므로 무조건 가입 완료라고 표시하지 않는다.

## Claude 연동

가입 후 세션을 받는다는 가정을 제거하고 ‘이메일을 확인해주세요’ 상태를 표시한다. 재발송은 `authClient.sendVerificationEmail({email,callbackURL:'/login'})`. 기존 클라이언트 객체에 있는 Better Auth 메서드를 사용한다.

로그인의 EMAIL_NOT_VERIFIED, 재발송 429 및 메일 장애를 처리한다. `/login`으로 돌아온 뒤 다시 로그인한다. URL의 error만으로 사용자 검증 상태를 바꾸지 않으며 실제 로그인/세션의 emailVerified를 사용한다. 확인 메일 발송 API는 계정 존재 여부를 숨기므로 200만으로 특정 계정이 존재하거나 실제 메일을 받았다고 단정하지 않는다.

이번 변경은 src/lib/auth.ts의 서버 설정만 포함한다. 화면 코드는 변경하지 않았다.

## 검증

실제 설치된 Better Auth + memory adapter + 대체 메일 전송으로 가입, 확인 전 로그인 차단, 재발송, 위조·만료 링크 거부, 정상 확인 후 로그인 성공, 자동 로그인 없음, 4번째 HTTP 재발송 제한을 검증했다. 실PG나 실제 메일 받은편지함·실 PostgreSQL rateLimit 테이블 검증은 아니다.
