# 비밀번호 재설정 서버 연결

2026-09-16. 설치된 Better Auth 1.7.1의 request-password-reset/reset-password 구현을 확인하고 기존 Resend 메일 어댑터와 연결했다. 프런트 화면은 수정하지 않았으며 실제 이메일은 보내지 않았다.

## 서버 동작

- AUTH_PASSWORD_RESET_ENABLED=false가 기본이다. 활성화 시 기존 Better Auth API에 발송 훅을 등록한다.
- POST /api/auth/request-password-reset: `{email}`. 정상 처리에서는 계정이 있는 경우와 없는 경우에 같은 안내 응답을 제공한다. 메일 공급자 장애 시 동일 응답을 보장하는 별도 처리까지 구현한 것은 아니다.
- 메일 링크는 고정 HTTPS 앱 origin의 `/reset-password#<token>`이다. 요청자의 redirectTo를 메일 링크에 사용하지 않는다. 토큰을 URL 쿼리로 전달하지 않는다.
- POST /api/auth/reset-password: `{token,newPassword}`. Better Auth가 토큰 검증과 비밀번호 변경을 처리한다. 토큰 유효 시간은 30분이며 사용한 토큰은 재사용할 수 없다. 비밀번호 최소 길이는 기존 정책인 8자다.
- 변경 후 기존 사용자 세션을 모두 폐기한다. 자동 로그인하지 않으며 이메일 확인 상태를 변경하지 않는다.
- 기능 활성화 시 DB 기반 요청 제한을 사용한다. 요청 재설정 경로는 60초당 3회, 변경 경로는 5회다. 이는 Better Auth 요청/IP 제한이며 이메일 주소별 전체 발송 한도는 아니다. 프록시의 클라이언트 IP 설정은 배포 시 검증해야 한다.

## 활성화 전 준비

인증 스키마 마이그레이션(rateLimit 포함), 실제 Resend 발신 도메인·메일 설정, HTTPS BETTER_AUTH_URL, 재설정 화면이 필요하다. 설정만으로 자동 활성화하지 않으며 실제 계정에서 요청→메일→변경→이전 세션 만료를 확인한 후 켠다.

## Claude 연결 참고

로그인 화면의 재설정 요청과 `/reset-password` 페이지를 연결한다. 토큰은 fragment에서 읽은 뒤 주소에서 제거하고 POST body로만 전달한다. 분석 이벤트·로그·외부 리소스에 넣지 않는다. 응답은 Better Auth 고유 형식이며 `/api/v1`의 `{data,meta}` 계약과 다르다.

요청 성공 시 계정 존재 여부를 단정하지 않는 안내를 사용한다. 오류·429·잘못되거나 만료된 토큰·짧은 비밀번호를 처리한다. 변경 성공 후 로그인으로 안내한다. 이번 Codex 작업에 화면 구현은 포함하지 않았다.

## 검증

설치된 Better Auth와 메모리 어댑터 테스트로 정상 계정/없는 계정 응답, 고정 앱 링크, 짧은 비밀번호 거부, 실제 비밀번호 교체, 기존 세션 삭제, 이전 비밀번호 거부, 토큰 재사용·만료 거부를 확인했다. 메일 설정 누락과 HTTP origin도 거부한다. 기존 이메일 확인 테스트 포함 4개와 전체 타입 검사·관련 ESLint 통과. 실제 DB 트랜잭션·동시 재설정·메일 전달·브라우저 화면은 검증하지 않았다.
