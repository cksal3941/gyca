# 라이브 모드 mock 잔재 감사 (Stage 4 — mock 잔재 감사)

작성: Claude · 기준: `NEXT_PUBLIC_API_MODE=live` 로컬 세션(PGlite + 브라우저, operator/participant 로그인)
목적: 라이브 모드에서 **아직 하드코딩/mock 데이터를 렌더하는 화면**을 전수 조사하고, 각 항목의 차단 원인(백엔드 계약 공백 / 인프라 / 결정 / 의도된 정적)을 분류한다. 출시 판단 시 "라이브인데 가짜 데이터가 보이는" 오해를 막기 위한 목록.

> 분류: **[라이브✅]** 이미 라이브 배선됨 · **[의도된 정적]** 마케팅/브랜딩 정적 콘텐츠(배선 불필요) · **[계약공백]** 공개 백엔드 API가 없어 배선 불가 · **[디자인위험]** 공개 계약에 편집 필드가 없어 배선 시 디자인 저하 · **[인프라/결정]** 실 데이터가 인프라·사업자 결정에 종속

## 결론

라이브 모드에서 mock이 남는 **공개 화면은 5종**: `/contests`(목록·상세), `/winners`, `/exhibitions`, 홈 마케팅.
- **의도된 정적**(about, 홈 마케팅): 배선 불필요 — 디자인 보호.
- **계약공백**(winners, exhibitions, contests 편집 메타): 배선하려면 **백엔드 공개 계약 추가**가 선행. 임의 배선 금지(디자인 저하·가짜 데이터).
- **인프라/결정**(실 수상작·전시): 심사·엔트리·S3·사업자 확정 이후 실 데이터 발생.

즉 남은 공개 배선은 모두 **백엔드 계약 신설 또는 인프라/결정 종속**이며, 프런트만으로 결정-불요·디자인-안전하게 진행할 수 있는 잔여 항목은 소진됨.
