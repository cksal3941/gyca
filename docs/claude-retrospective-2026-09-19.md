## 1. 한 줄 요약

**화면·배선은 결정·인프라 없이 만들 수 있는 범위까지 거의 다 됐다(~80%).** 남은 ~20%는 전부 (A) 대표/코덱스의 **결정**, (B) **외부 계정/인프라**, (C) **백엔드 공개 계약 신설**에 막혀 있다. 지금 필요한 것은 코드가 아니라 **결정과 계정**이다.

## 3. 미완 + 사유 (전부 게이팅 — 제가 지금 못 하는 이유)

| 남은 기능 | 분류 | 구체적 차단 |
| --- | --- | --- |
| 공모 **오픈**(실접수 시작) | 결정+인프라 | consents·guardian_policy·payment_policy·payment_routes·storage·checkout·retention·live_payment 미충족 |
| **보호자 동의**(청소년 접수 필수) | 결정+인프라+플래그 | `request()`가 메일러+HTTPS origin 강제(로컬 503), **토큰은 이메일로만 전달·응답에 없음→로컬 검증 불가**, `GYCA_GUARDIAN_CONSENT_ENABLED` 기본 OFF, 보호자 정책 미확정 |
| 결제 mutations(지연승인/재큐/환불) | 인프라 | 실주문 + PG + 사업자 필요 |
| 결과 발표·인증서 발급 | 인프라 | 엔트리 + 심사 완료 + S3 필요 |
| 아카이브(winners/exhibitions 공개) | 백엔드 계약 | **공개 결과/전시 API 계약 자체가 없음**(`result-admin`만 존재) |
| contests 목록 라이브화 | 백엔드 계약+디자인 | 공개 `Competition`에 편집필드(summary/category/city/period/포스터) 없음 → 배선 시 디자인 저하 |
| 홈 마케팅(PartnerMarquee/NewsUpdate) | 디자인 보호 | 레퍼런스 레이아웃 보호 대상(임의 라이브화 금지) |
| 프로필 편집(마이페이지) | 백엔드 계약 | 프로필 편집 계약 없음 |

> **정직성 주의:** 위 항목은 "화면이 없어서"가 아니라 "결정/계정/백엔드 계약이 없어서" 막힌 것. 임의 값·가짜 데이터·블라인드 배선으로 채우지 않았음(검증 불가한 것은 만들지 않음).

## 4. 결정 인계 — 코덱스가 정할 수 있는 것 vs 대표만 정할 수 있는 것

사용자 요청대로 결정권을 코덱스에 넘긴다. 단, **모든 결정을 코덱스가 정할 수는 없다** — 사업자·법률·외부계약은 사람(대표)만 가능. 아래처럼 나눠 인계한다.

### (가) 코덱스가 정하고 진행할 수 있는 것 (기술/정책 구조·안전 기본값)
- **consents 문서 구조·버전 체계**: 참가규정/개인정보/작품이용허락 3종의 스키마·버전 규칙·다국어 처리 방식. (실제 법률 문구는 대표 검토 필요하나, 골격·플레이스홀더·버전 관리는 코덱스가 결정 가능.)
- **retention(보관 기간) 기본 정책값**: 법정 최소치 기반 초안 제시 후 대표 승인. 코덱스가 근거와 함께 권고안 작성.
- **아카이브(winners/exhibitions) 공개 API 계약 신설**: 결과/전시 공개 엔드포인트·스키마 설계. (순수 백엔드 계약 작업 — 코덱스 영역.)
- **contests 공개 목록 편집필드 확장**: 공개 `Competition`에 summary/category/city/period/cover를 추가할지 결정·계약화. (결정 시 프런트가 라이브 배선.)
- **guardian 기능 플래그 on/off 운영 방침** 및 dev 검증 경로(테스트 메일 or 토큰 노출) 마련.
- **프로필 편집 계약 신설 여부**.

### (나) 사람(대표)만 정할 수 있는 것 — 코덱스도 못 함
- **사업자 등록·법인 국가·PG 계약**(예: 해외결제 PG 신청/승인), **청구·정산 통화**(현재 €70=EUR 가정), 해외카드/참가국 범위, 환불 방식. → `operator-decisions-needed.md` A
- **참가비·마감 시각·시간대·결제 유예** 확정값. → B·C
- **필수 입력 필드·업로드 규격(형식/용량/최소페이지)** 최종 확정값. → D (편집 화면은 완비, 값만 필요)
- **국가별 보호자 연령 기준·동의 근거**. → E
- **외부 계정**: 클라우드/DB/S3/메일(Resend 등)/PG 테스트키, 관리자 초대. → F
- **전시 명칭·장소 승인, 사업자 표시정보, 아카이브 실자료**. → G

## 5. 결정되면 어떻게 풀리나 (해제 순서)

1. **외부 계정(F) + PG(A)** 확보 → DB/S3/메일/PG 연결 → 업로드→제출→주문→결제 **풀 E2E** 검증 가능.
2. **정책 값(B·C·D·E)** 확정 → 이미 완비된 **등록 화면에 입력** → launch-readiness 충족 → **공모 오픈**.
3. **consents/retention 문서(가·나 협업)** 확정 → 동의 흐름 + 개인정보 보관 정책 완성.
4. **보호자 동의**: 플래그 on + 메일 + 정책 → 참가자 요청/보호자 수락 페이지 배선(계약 확인됨, 배선만 남음).
5. **아카이브/contests 공개 계약(가)** 신설 → 프런트 공개 배선.

각 항목은 화면·어댑터 골격이 이미 있어 **결정·계정만 붙으면 배선·검증은 빠름**.

## 6. 미결(100%로 미룬 항목)
- **결과 발표 관리자 화면**: `result-admin` 계약 존재하나 심사 데이터 없어 "엔드포인트 도달" 수준까지만 검증 가능 → 데이터 확보 후.
