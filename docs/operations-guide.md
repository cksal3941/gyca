# 운영 가이드 (관리자용) — 초안

작성: Claude · 기준: `docs/claude-fullstack-work-order-2026-09-19.md` §11 · 현재 구축된 기능 기준
> 로컬/스테이징 검증 기준. 실제 오픈은 외부 검증(저장소·보관·PG)과 사용자 승인 후.

## 1. 운영자 계정·권한
- 운영자(organizer)는 전체 관리 화면 접근 권한. 부여는 `scripts/manage-organizer.mjs`(계정 대조·미리보기·감사) — 운영에서는 승인된 사람만.
- 공모별 결제 권한은 `scripts/manage-payment-access.mjs`로 별도 관리(전역 organizer와 다름).
- 심사위원은 가입 후 운영자가 `관리자 → 심사 운영`에서 활성화.
- 일반 참가자는 관리 화면 접근 시 403.

## 2. 공모 등록·수정·오픈 (`관리자 → 공모 관리`)
- **등록/편집**: 슬러그·제목(EN/KO)·참가비(EUR minor)·시간대·일정(UTC 저장, 공모 시간대 표시)·부문·연령·입력 필드·업로드 규격·요강. 운영 값은 직접 입력(기본값 임의 확정 안 함).
- **오픈 조건(launch-readiness)**: `공개(published) + 폼(부문·연령·필드·표지 이미지·도서 PDF≥20쪽) + 동의문 + 보호자/결제 정책 + 저장소·보관·실결제 검증`이 모두 충족돼야 “접수 열기”가 됩니다. 미충족 항목은 화면에 표시되며, 외부 검증이 필요한 항목(storage/retention/live_payment)은 실제 증거 없이는 충족 처리하지 않습니다.
- **오픈/중단/재개**: 편집 화면의 “오픈 제어”에서 사유(감사 기록)와 함께 처리. 일시 중단은 신규 접수만 막고 기존 제출 건 결제 정책은 유지.

## 3. 접수 운영 (`관리자 → 접수 관리`)
- 검색(접수번호·참가자·작품명)·상태/결제/결과 필터·정렬·페이지네이션. 검색 변경 시 선택 초기화.
- **상세**: 참가자·작품·파일 검증 상태·결제(읽기전용)·동의·인증서·처리 이력(최대 100건). 참가자 원본 파일은 관리자 화면에서 직접 다운로드하지 않음.
- **CSV 내보내기**: 현재 검색·필터·정렬 전체 조건으로 다운로드(개인정보 포함 — 취급 주의).
- 완료된 결제는 이 화면에서 변경하지 않음.

## 4. 결제 운영 (`관리자 → 결제 운영`)
- 대시보드: 계정·지원자·공모별 접수/결제 카운트·승인액(환불 전 총액, 정산 매출 아님).
- 공모별 결제 건강도(payment-health)와 검토 필요 주문(payment-reviews) 조회.
- 지연 승인 확정·복구 재큐·환불은 서버 API + 권한으로 처리(현재 화면은 조회 중심, 실행은 PG 연결 후 확장). 버튼 클릭을 최종 성공으로 간주하지 않고 원장을 재조회.

## 5. 심사 운영 (`관리자 → 심사 운영`)
- 심사위원 활성/비활성. 공모별 채점 기준(항목·배점 1~100, 제출 후 수정 허용 여부) 편집.
- 배정·블라인드 파일 승인·결과 발표·인증서 발급은 제출된 접수와 저장소(S3) 준비 후 진행. 발표는 라운드 단위 원자적 처리(임의 행 반복이 아님).

## 6. 공개 콘텐츠 (`관리자 → 콘텐츠 관리 / 협력기관`)
- 공지·일정·FAQ·뉴스·보도: 초안 생성 → 공개/보관. 초안·공개 항목은 **수정** 가능(분류·슬러그는 고정). 본문은 일반 텍스트(HTML 미지원). 공개된 항목만 공개 사이트(/notices, 상세 /notices/{slug})에 노출(공개 GET 최대 60초 캐시).
- 협력기관: 초안 → **관계 확인(증거·사유)** → 공개. 관계 확인 전에는 공개 불가. 철회 시 비공개. 초안·공개 항목은 **수정** 가능(유형·슬러그는 고정).

## 7. 개인정보 요청 (`관리자 → 개인정보 요청`)
- 참가자는 마이페이지(개인정보 탭)에서 **계정 삭제·데이터 파기**를 요청. 검토 시작 전까지는 참가자가 스스로 취소 가능.
- 운영자 처리: 접수됨 → **검토 시작** → (보존 의무 시 **보존 보류**: 사유코드+증거 필수) ⇄ **검토 재개** → **파기 승인**.
- **파기 승인은 비가역**(파기 실행으로 이어짐). 화면에서 승인은 별도 확인 단계를 거침. 법적·결제·공모 증빙 보존 의무가 남아 있으면 승인하지 말고 보존 보류로 둘 것.
- 모든 보류/승인은 증거 참조(문서 ID·링크)로 감사 기록을 남김.

## 8. 장애·복구 (요약)
- 결제/웹훅 지연·중복·응답 유실: 서버가 멱등·복구로 접수번호를 정확히 한 번 보장(설정 시각 기준). 이상 청구는 검토 대상으로 남김.
- 메일 실패: 접수(received)는 유지, 발송만 재시도.
- 상세 장애 시나리오·부하 목표는 `docs/staging-readiness.md` 및 실검증(단계 8)에서 다룸.

## 9. 미결(사용자/외부 결정 대기)
- PG·통화·사업자, 저장소/보관/메일 계정, 정책 문구·보호자 정책, 참가비·환불·마감 시각 등 → `docs/operator-decisions-needed.md`.
- 실제 운영 오픈은 위 결정 + 외부 검증 증거 + 사용자 승인 후. 테스트 키·이전 revision 증거로 오픈하지 않음.
